# 开发方案与过程

## 1. 当前基线

仓库当前具备：Forge 1.20.1 / 47.4.28、Java 17 工具链、Gradle Wrapper 8.8、最小 `@Mod` 入口、Create 及其开发期依赖、可选 Create 模组声明和 GitHub Actions 构建工作流。

仓库当前不具备：蓝图物品/GUI、轨道注册与铺设、轨道 SavedData、社区模型扫描、Schema 校验、接触网、列车、站台、调度或 Create 兼容代码。后续开发以本文件阶段验收为准，不能把目标文档当成功能完成证明。

## 2. 推荐架构

### 分层

```text
com.fastjim.vastseatrain
  VastseaTrain                 模组入口与生命周期
  api                          稳定后公开的注册 API
  content                      方块、物品、菜单与实体注册
  blueprint                    蓝图配置、计划、校验与施工
  track                        线形、拓扑、道岔和持久化
  catenary                     接触网参数与铺设
  vehicle                      列车/车辆定义与运行表现
  station                      站台、信号与调度接口
  community                    manifest、扫描、Schema、注册表和隔离
  client                       GUI、渲染、预览和客户端资源
  compat.create                可选 Create 适配，不能被核心静态引用
```

实际目录可随实现细化；跨层依赖应朝向核心数据模型。客户端渲染类不从服务端初始化路径加载。Create 专属类和注册代码集中在 `compat.create`，核心不得 import Create 包。

### 领域数据

- `BlueprintConfig`：玩家选择的线形、参数、部件 ID、接触网配置及版本。
- `TrackPlan`：纯数据施工计划，包含坐标、朝向、轨道基元、连接关系、资源需求和校验结果。
- `TrackNetwork`：自有线路节点、端点、连接和道岔路线；存档格式必须有版本并提供迁移策略。
- `CommunityModelDescriptor`：经校验的资源 ID、作者、许可、版本、类型、标签、依赖和类型参数。
- `CreateTrackAdapter`：只在 Create 已加载时建立的边界对象，不作为核心网络的持久化权威。

蓝图生成和几何运算尽量使用不依赖世界对象的纯逻辑，使单元测试不需要启动 Minecraft。所有真实世界修改由服务端在验证完成后执行。

## 3. Create 可选依赖策略

1. `mods.toml` 中 Create 依赖保持 `mandatory = false`；无 Create 的启动是核心验收条件。
2. 核心包不直接引用 Create 类、注解、枚举、字段类型或静态初始化器。
3. Create 兼容放在独立包/源集；事件订阅仅在 Create 存在时注册。检查 FML 扫描和链接行为，避免仅靠 `if (ModList...)` 包住一个已被 JVM 验证的 Create 类型。
4. 第一项兼容工作是最小 POC：自有直轨被 Create 列车发现、列车通过一段线路、基本端点连续。POC 失败时先评估适配方向，不在核心引入 Create 硬依赖。
5. 后续分别验证道岔选路、列车进出网络、速度和方向、区块加载/卸载、拆轨/重建、世界保存/加载、客户端渲染，以及服务端无 Create 的启动。
6. 开发运行配置可以提供带 Create 的兼容配置；独立配置不得依赖该运行时模组。正式发行不把 Create 或其库打进 VastseaTrain jar。

Create 的运行时轨道网络与本模组自有拓扑可能采用不同模型。兼容目标是可验证的行为契约，不预设必须把一方数据直接覆盖成另一方数据。

## 4. 分阶段计划与验收

### 阶段 0：工程与规范基线（当前）

- 固定版本、包名、Mod ID、CI 和文档入口。
- 建立需求大纲、开发方案、美术交付规范、社区 manifest Schema 草案。
- 验收：Java 17 下 `gradlew build` 成功；CI 可构建；无 Create 为可选依赖；文档明确未实现能力。

### 阶段 1：基础框架、蓝图 GUI 原型、社区扫描骨架

- 注册蓝图物品；空气右键打开三栏 GUI，先用占位数据完成交互布局。
- 定义配置版本、客户端/服务端包和空计划模型。
- 实现资源目录约定、Schema 校验入口、最小可用示例包及逐项错误报告。
- 验收：GUI 三栏职责清晰；配置可保存/重载；无 Create 启动核心；非法 manifest 被隔离；不执行包内代码。

### 阶段 2：轨道选择、预览和基础铺设

- 选择轨道/扣件/枕木/道砟/桥面资源；注册表内容进入 GUI 下拉列表。
- 实现一米轨道模型预览、低开销旋转和缺失资源标记。
- 实现水平直线，再扩展曲线参数；建立全量预检、区块/权限检查、施工上限和失败不落方块规则。
- 验收：直线施工可重复、可保存和拆除；非法计划不改世界；模型缺失有日志定位；性能上限有测试。

### 阶段 3：轨道结构与道岔

- 将轨道结构拆分为可组合部件；实现道岔、路线状态、护轨和外轨超高的几何表达。
- 为直轨/曲线/道岔建立连续拓扑与保存迁移。
- 验收：连接关系和道岔状态保存/重载一致；结构无悬空/冲突；复杂计划失败可回滚。

### 阶段 4：电气化与接触网二级菜单

- GUI 中实现接触网类型、支柱、悬挂、导线、绝缘子、跨距、高度、张力/下垂和模型选择。
- 使接触网计划与轨道路线参数协同，按几何分段布置。
- 验收：所有参数有默认值、单位、范围和预览；边界值校验；轨道与接触网计划原子化。

### 阶段 5：列车、物理、站台与调度

- 逐步实现车辆定义、转向架/连接点、受电弓、动画、碰撞与声音挂点。
- 提供火车/高铁/地铁场景的站台设备、信号/调度设备和调度图数据接口。
- 验收按子系统拆分；每种模型参数有默认值和范围；服务端权威运行状态可保存恢复。

### 阶段 6：Create 可选兼容与社区发布工具链

- 从直轨 POC 扩展到列车连续运行、线路接入、道岔控制、速度/方向和网络生命周期。
- 发布模型模板、Schema、示例包、离线校验器、预览/导入向导和 API 文档。
- 验收：无 Create 安装完整启动且测试通过；有 Create 时兼容场景逐项有游戏验证记录；失败模型不影响核心；模板可直接校验。

阶段可并行准备规范与资源，但阶段验收不可用尚未验证的未来功能替代。

## 5. GUI 与蓝图流程要求

- 左栏：类型/分类、搜索、作者、标签、收藏、可用性和模型组合。
- 中栏：稳定尺寸的一米轨道预览；社区模型旋转预览；错误资源显示明确状态；接触网设置入口打开二级界面。
- 右栏：直线、弯道、道岔、自定义曲线和未来线形；只显示对应参数，所有参数标明单位、默认值和有效范围。
- 玩家对空气右键打开 GUI；服务端验证物品、权限、配置版本和可执行动作。
- 配置只保存稳定资源 ID 和数据参数，不保存类名、脚本或任意资源加载路径。

## 6. 安全、性能与兼容

- 资源只从受信任的 Minecraft ResourceManager/DataPack API 读取；路径规范化后拒绝绝对路径、`..`、重复 ID 和越权 namespace。
- 扫描采用逐包/逐模型异常捕获；记录 namespace、模型 ID、资源路径和根因；不吞掉 VM 错误。
- 为包体、JSON 深度、模型面数、纹理尺寸、动画数和预览资源设置可配置上限，并限制扫描/解码工作量。
- 资源注册以不可变快照发布；资源重载时原子替换，旧快照只在安全边界回收。
- 核心服务端逻辑不依赖客户端类；社区输入不能触发任意代码执行。
- 变更存档格式时增加版本迁移测试；网络协议需显式版本与服务端校验。

具体资源上限在取得代表性模型和性能基准后定值，不在未测量前承诺单一固定上限。

## 7. 开发与构建过程

1. 先更新本文件/模块文档中对应阶段和验收，再实现可独立检查的小步骤。
2. 几何、参数和 manifest 校验优先写不启动游戏的单元测试；Forge 注册与渲染再用 IDEA 手动游戏验证。
3. 本地检查：`./gradlew build --no-daemon`（Windows 使用 `./gradlew.bat build --no-daemon`）。
4. `build` 通过后立即创建正常提交并使用普通 `git push` 推送；保持线性项目历史，不使用强制推送或改写远端历史。GitHub Actions 对 `main` push、PR 和手动触发执行同一构建。
5. 检查远端 Actions 对应提交的结论。远端失败时先读失败步骤，修复后重建，再立即上传。
6. 除非用户明确要求，不运行 `runClient`、`runServer` 或 GameTest 启动器；游戏内验证由用户在 IDEA 执行。

## 8. 每阶段交付物

- 可运行代码与针对性自动化测试。
- 变更后的用户/开发/美术/社区规范文档。
- 示例资源或迁移说明；涉及资源格式的变更同步更新 Schema 和模板。
- 构建记录与必要的人工游戏验证记录；没有执行的验证明确标注为未验证。
