# 美术对接文档

## 1. 目的与当前状态

本文定义 VastseaTrain 模型资源的交付约定，覆盖轨道、扣件、枕木、道砟、桥面、列车、接触网、站台和信号/调度设备。

资源加载器、旋转预览和游戏内模型 API 目前尚未实现。交付前由程序确认目标渲染格式和坐标适配；本规范是资产制作基线，不表示所有格式当前已经能在游戏中载入。

## 2. 通用命名与目录

资源全部放在模组或资源包的 namespace 下，路径小写 ASCII，禁止空格、大写、反斜杠和 `..`。同一命名空间内 ID 不重复。

```text
assets/<namespace>/
  community/<type>/<model_id>/manifest.json
  models/community/<type>/<model_id>/...
  textures/community/<type>/<model_id>/...
  animations/community/<type>/<model_id>/...
  previews/community/<type>/<model_id>/...
```

运行时资源 ID 使用 `namespace:path`。manifest 的 `model`、`textures`、`animations`、`preview` 指向上述资源中的完整资源 ID；不得使用本机绝对路径或包外文件系统路径。

## 3. 坐标、尺度與枢轴

- 建模比例按 Minecraft 世界单位交付，`1 block = 1 m`；尺寸参数用明确单位，不能把毫米数直接当方块坐标。
- 通用局部坐标采用 Y 向上；轨道局部前进方向约定为 +Z，横向为 X。坐标适配器如需转换，必须由程序统一处理，不在同一资产内部混用轴向。
- 轨道原点默认放在轨道段几何中心的轨面基准处；钢轨轨顶为局部 `Y=0`，下方结构使用负 Y。道岔/弯道原点与端点由对应 manifest 参数定义。
- 轨距默认物理参数为 1435 mm；比例模型必须保持申报轨距。1 m 预览显示的是一米长度轨段，不是把模型缩放成宽度一米。
- 车辆原点、转向架、车钩、受电弓和碰撞箱必须使用独立挂点数据；挂点名称与模型动画名称保持稳定。
- 支柱模型原点建议设在地面安装面；站台设备原点设在安装底面；桥梁段明确起终端连接点和允许拼接面。

具体渲染坐标、正面方向或 OBJ/JSON 适配若与目标渲染器不一致，以程序提供的验证样例为准，并更新本文件。

## 4. 类型交付要点

### 轨道及轨道部件

- 声明长度、轨距、线形/曲线参数、端点连接位置与方向。
- 轨道、扣件、枕木、道砟可分件组合；声明枕木间距、扣件位置和可重复铺设范围。
- 道岔需提供旋转/切换部件、轴心、路线端点、状态命名和动画时长；固定摆拍模型不能作为可动道岔交付。
- 护轨、外轨超高、桥面与碰撞/占位需分别说明，不把视觉模型误作碰撞定义。

### 列车

- 提供车辆原点、前向、转向架中心、车钩连接点、门/受电弓挂点、碰撞箱和建议轴距。
- 动画状态使用稳定名称，并提供默认/缺省状态；提供无动画静态回退模型。
- 车辆长度、宽度、高度、质量建议值和声音挂点以类型参数申报，物理有效范围由代码 Schema 约束。

### 接触网

- 分别交付支柱、悬挂装置、导线、绝缘子等可组合件；定义安装点、导线连接点、支柱底面和轨面高度基准。
- 声明跨距、高度和张力/下垂表现所需参数；下垂曲线不能只依赖一张固定弯曲网格。
- 说明直线、曲线和道岔附近的适用范围及拼接方式。

### 站台、信号与调度设备

- 声明安装朝向、交互点、显示面朝向、地面基准和适用场景（火车/高铁/地铁）。
- 显示内容和调度接口是逻辑数据，不烘焙进不可编辑贴图；屏幕需提供合理的空白/离线视觉状态。

## 5. 贴图、面数与动画

- 纹理首选 PNG，资源必须位于 `textures/`。透明物件标注 Alpha 需求；不透明纹理避免无意义全透明通道。
- 贴图尺寸建议使用 16/32/64 像素倍数并按模型重要性控制；具体上限由项目性能测试确定。
- 法线、发光、粗糙度等附加贴图只有在目标渲染器明确支持后才作为必需资产；必须同时提供基础色回退。
- 模型面数、骨骼数、动画数量和单资源大小在提交 manifest 时记录；禁止在无性能预算下提交无限细分模型。
- 动画提供默认姿态、状态命名、单位和循环/一次性说明；提供静态回退资源。

## 6. 文件、版权与许可

每个模型必须有独立 `manifest.json`，至少提供 Schema 中的必填字段。`author` 和 `license` 不可空缺；不得把未知来源或无授权模型标成可自由分发。

推荐一并提供可编辑源文件（如 `.blend`）作为非运行时附件，并注明 Blender/插件版本。运行时模型只使用项目确认支持的格式；`.blend` 不作为游戏直接加载格式。

## 7. 提交清单

- [ ] Namespace、模型 ID、路径全小写且唯一。
- [ ] manifest Schema 校验通过，作者、许可和兼容版本已填写。
- [ ] 模型尺寸、轴向、原点、轨距/连接点和适用线形已说明。
- [ ] 所有贴图可解析且位于 `textures/`；没有外部绝对路径。
- [ ] 动画有默认状态和静态回退；道岔状态能对应路线定义。
- [ ] 提供预览图或预览模型，缩略图裁切不遮挡主体。
- [ ] 无缺失部件、材质、依赖或无法解释的版权来源。
- [ ] 附带游戏截图/渲染器预览；尚未游戏验证的资产须标注。

## 8. 接收与反馈流程

1. 美术作者复制 `examples/community-models/minimal/manifest.json`，替换 namespace、ID、作者和许可。
2. 将模型/贴图放进约定目录，填写类型参数和依赖。
3. 先运行 Schema/路径/资源存在性校验；程序提供适配器预览后再做游戏内检查。
4. 程序确认坐标、资源加载、包内隔离和性能后标记为可集成；需要修改时反馈具体资源 ID、字段、坐标或日志定位。
5. API/渲染格式变化需升级兼容版本并保留迁移说明，不静默改变资产语义。
