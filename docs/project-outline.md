# VastseaTrain 项目大纲

## 1. 项目定位

VastseaTrain 是面向 Minecraft 1.20.1 Forge 的独立轨道交通模组，目标是建立可扩展的轨道、列车、电气化、站台和调度系统。模组展示名称直接使用项目名 `VastseaTrain`，不添加副标题。

这是长期目标，不代表当前功能已经实现。当前仓库只包含 Forge 开发环境、最小模组入口和依赖/CI 基线。蓝图、轨道、列车、GUI、社区资源导入和 Create 兼容均待开发。

## 3. 产品目标

- 提供独立可用的轨道交通核心，不要求安装 Create。
- 用蓝图配置工作流生成直线、曲线、道岔和后续自定义线形。
- 逐步建立轨道结构、可动道岔、护轨、超高、电气化、列车、站台和调度能力。
- 面向火车、高铁、地铁等场景提供可组合、风格统一的表现与设备。
- 提供资源包/数据驱动内容和 Java API 两条扩展路径，降低社区模型作者门槛。
- 单个社区内容包出错时隔离该内容，不拖垮其他内容或基础模组。
- Create 兼容独立于核心；安装 Create 后再尝试接入其列车网络和运行逻辑。

## 4. 系统边界

### 核心模块

- 轨道几何、轨道拓扑、铺设计划、施工预检和回滚。
- 蓝图物品、配置数据、GUI 与客户端/服务端同步。
- 轨道、道岔、电气化、站台、调度等自有游戏内容。
- 社区资源发现、manifest 校验、注册表、预览数据与诊断日志。
- 不引用 Create 类型；不因 Create 缺失而改变核心类加载路径。

### 可选兼容模块

- Create 存在性探测和单独的兼容适配。
- 自有轨道与 Create 轨道图之间的几何/拓扑映射。
- 速度、朝向、车辆端点、道岔选路和生命周期适配。
- 无 Create 安装时不注册、不加载含 Create 类型引用的适配类。

### 社区内容路径

- 资源包提供模型、贴图、动画和预览资源。
- 数据包提供可安全解析的 manifest、样式预设和参数配置；数据包本身不替代资源包提供渲染几何与贴图。
- Java API 面向需要自定义行为、方块或渲染器的模组开发者。
- 三条路径共享命名空间、ID、版本、依赖和校验规则；无代码内容不得执行代码。

## 5. 核心用户流程

1. 玩家取得蓝图，在空气上右键打开配置界面。
2. 左栏筛选轨道部件/社区模型；中栏查看一米轨道预览并进入接触网二级菜单；右栏选择线形并设置其参数。
3. 蓝图生成铺设计划。客户端预览范围、碰撞和缺失部件；服务端再次验证权限、区块、方块状态、数量及拓扑。
4. 验证完整通过后执行施工；失败时不留下半条线路，并记录可定位的原因。
5. 已注册模型按类型、作者、标签、收藏状态和兼容性筛选；错误模型显示不可用原因但不阻断其他模型。

GUI 的搜索/过滤、模型选择、轨道配置和接触网配置都属于目标设计，分阶段实现。

## 6. 目标模块清单

| 模块 | 主要职责 |
| --- | --- |
| 蓝图与 GUI | 空气右键入口、轨道参数、模型选择、一米预览、接触网二级菜单 |
| 轨道几何与施工 | 直线/曲线/道岔/自定义曲线、预检、计划、施工和回滚 |
| 轨道结构与设备 | 钢轨、扣件、枕木、道砟、护轨、超高和桥面等扩展部件 |
| 电气化 | 支柱、悬挂、导线、绝缘子、跨距、高度、张力/下垂和铺设协同 |
| 列车与物理 | 车辆模型、编组连接、转向架、碰撞、运动、动画和音效挂点 |
| 站台与调度 | 场景化站台设备、交互点、调度图数据和信号设备 |
| 社区内容 | manifest、资源发现、注册、校验、缓存、预览、诊断和版本迁移 |
| Create 兼容 | 可选轨道图适配、列车接入、道岔控制与速度/方向映射 |

## 7. 非目标与约束

- 不在第一阶段承诺完整列车物理、完整调度系统或所有曲线铺设。
- 不在无证据时宣称 Create 列车可以自动使用自有轨道或遵从自有道岔；必须通过兼容原型逐项验证。
- 不允许运行社区包中的脚本、字节码或任意 Java 代码。
- 不承诺 Minecraft 原生资源包能独立提供所有游戏逻辑；需要行为的内容走数据驱动配置或 Java API。
- 模型版权和许可必须明确；示例资源也需采用可再分发许可。

## 8. 决策记录

- 核心模组与 Create 兼容分层，Create 是 `mods.toml` 中的可选依赖。
- 主世界线路模型以 VastseaTrain 自身数据为权威；Create 兼容通过适配层交换运行时信息。此方案仍需原型验证，不提前锁定 Create 内部实现细节。
- 社区无代码导入以声明式 JSON 与 Minecraft 资源为基础，采用严格路径校验、大小限制和逐项隔离。
- 蓝图铺设必须使用客户端预览 + 服务端权威复核，不能信任客户端提交的最终方块计划。
